## Top 3 porting risks

1. **Observability is the sequencing gate.** ~Half the EF-361 tests assert `Strategy=`/`Command=`/`Targets=` message segments or event payloads that don't exist on release. Tasks 4+5 must land first, in Diagnostics + executor, and they touch all 8 event call sites and the two public EventData types. Porting any Phase 2–6 task without them produces tests that cannot discriminate (the exact failure mode the ledger documents for Task 17's evidence finding).
2. **EF-168/EF-478 changed the setter pipeline under Tasks 7/8/9/22.** `BuildSetter` is a different function now (`IPropertyBase` targets, `StructuralPath` dotted paths, `ThrowIfSetterPathsOverlap`'s documented last-wins, `$literal` wrapping, complex null refusals, `ThrowIfBulkMisreadsNullElements`). Guards must be re-derived against that pipeline, and Task 9's duplicate-setter rejection has to explicitly overturn (or preserve) the new last-wins doc comment — plus Task 22's owned-rejection test is now wrong by design.
3. **The two remaining "final-review" traps travel with the port.** (a) Task 24 must be the rewritten clean-rejection suite (QE forbids multi-document writes) or it ships CI-only tests that can never pass; (b) widening `ClassifyBulkSource` (Tasks 13/15) requires widening `MongoBulkPlanBuilder.BuildFilter`'s Where-only walk in step — currently it throws on any non-Where — and the ledger's Task 13 directive (never add OfType/Cast to the neutral set) plus the Task 15 `OfType<TDerived>()`-self-referencing guard must both be carried, or a classification miss silently deletes the wrong documents.
